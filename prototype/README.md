# Prototype: foreground-responsive scheduling (slice 1)

Governed by [instructions.md](../docs/instructions.md); current research plan in
[agentic-offload-prototype-plan.md](../docs/agentic-offload-prototype-plan.md) (revision 5).
The implemented baseline is one Python process with direct calls and no gRPC.
ANE operator lowering, small-model execution and a later gRPC demonstration are planned;
they are not implemented yet. NEXUS is never imported or called by this baseline.

## Setup

```bash
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python -r requirements.txt        # harness + TF-IDF router
uv pip install --python .venv/bin/python -r requirements-mlx.txt    # only for the MLX generator
```

## Run

```bash
.venv/bin/python -m pytest tests -q                                  # contracts, lifecycle, failure paths
.venv/bin/python -m prototype.run_replay --config configs/baseline.json   # no priority (baseline)
.venv/bin/python -m prototype.run_replay --config configs/priority.json   # priority at token boundary
.venv/bin/python -m prototype.run_replay --config configs/fault-injection.json
```

The MLX generator reads models from `cache.nosync/hf` (prototype-owned `HF_HOME`); the pinned
model is `mlx-community/Qwen2.5-3B-Instruct-4bit`, weights hash recorded in each manifest.

Each run writes `results/<run-id>/{manifest.json,requests.jsonl,summary.json,report.md}`.
`configs/*.json` select `router` (`keyword` | `tfidf`) and `generator` (`fake` | `mlx`).
Fake results prove plumbing only; they support no speed or quality claim.

## Workload

`prototype/bench/workload/replay.jsonl` holds the 60 frozen requests; `train.jsonl` fits the
TF-IDF router. Both are generated by `build_workload.py`, and no scenario family appears in both.
Do not edit `replay.jsonl` after a baseline is recorded; add a new file instead.

## Limits and recovery

- Bounded queues: `fg_capacity` / `bg_capacity`; overflow is a typed `queue_full` rejection.
- Deadlines: `deadline_ms` per class, checked at every stage and token boundary.
- Router: one fallback to the keyword router on timeout, error or invalid output; never a second.
- A stuck router thread is abandoned, not killed; it ends when the backend call returns.
- Recovery: nothing outside this directory is modified. Delete `results/` and `.venv/` to reset.

## ANE experiments (revision 5, R0/R1)

Native probe and projection lowering against the pinned ane.cpp runtime (`prototype/ane/vendor/PIN.json`).

```bash
bash prototype/ane/vendor.sh                                   # shallow clone at the pinned commit; writes vendor/PIN.json
cmake -S prototype/ane -B prototype/ane/build -G Ninja \
  -DCMAKE_C_COMPILER="$(xcrun -f clang)" -DCMAKE_CXX_COMPILER="$(xcrun -f clang++)"
cmake --build prototype/ane/build                              # builds ane_runtime (upstream core only), probe, bench_main
prototype/ane/build/probe --check                              # exit 0 = private ANE runtime available
.venv/bin/python prototype/ane/shapes.py q_proj                # export a real BF16 projection + full sha256 into prototype/ane/fixtures/
.venv/bin/python -m prototype.ane.benchmark --r0               # results/ane-r0-feasibility/
.venv/bin/python -m prototype.ane.benchmark --r1 [--quick]     # results/ane-r1-projection/ (numerics gates, 3 timing windows per path, stability)
.venv/bin/python -m pytest tests -q -m ane                     # hardware-marked numerics test; skipped without the build
```

Notes:
- Use the Ninja generator. The Make generator fails on the colons in this workspace path.
- Only `core/ane_runtime.cpp` is built from upstream; `compat.cpp` supplies two `Timer` statics upstream defines in model code we do not build.
- The runtime keeps a compile-marker cache in `~/Library/Caches/ane_lm/compiled_markers/` and compile directories under `$TMPDIR/<modelId>/` (persist cache is enabled so `model.mil` can be recorded).
- `bench_main` timing is host wall time around a synchronous evaluate; it is not a hardware counter. Energy and per-operator placement need root `powermetrics`, which is a manual, optional step.
- Model weights for shapes come from `Qwen/Qwen3-0.6B` in the prototype-owned `cache.nosync/hf`; the exported `.bin/.npy` fixtures are gitignored, their sha256 is in `fixtures/*.json`.

## Two-device scenario (manual trial)

```bash
M=$(ls -d "$PWD"/cache.nosync/hf/hub/models--Qwen--Qwen3.5-4B/snapshots/*/ | head -1)
ANE_WORKERS=1 .venv/bin/python -m prototype.scenario_parallel --ane-model "$M" --sessions 1 --run-id scenario-<name>
```

Runs three conditions (GPU-only serial; ANE extraction overlapped with GPU drafting; ANE then GPU) on the 8 notes in
`prototype/scenario_notes.json`, writes `results/scenario-<name>/{summary.json,report.md,briefing-*.md,ane-serve.log}`.
Keep `--sessions 1` and `ANE_WORKERS=1`: batched serve sessions corrupt every lane but the first on this build (see plan, Finding 1).
Needs the full binary (`prototype/ane/ane.cpp-bin`, built with Rust in `~/.cache/ane-cpp-build-full`), ≥ 12 GB free disk for the
ANE compile cache of a 4B model, and the Docker VM stopped if the 27B GPU model is used (memory).

## R3 model-level comparison

```bash
bash prototype/ane/r3/build_variants.sh              # builds r3/bin/ane-trace and ane-exp outside the workspace (Rust needed)
.venv/bin/python -m prototype.ane.r3.run_eval [--model Qwen/Qwen3.5-4B]   # 30 frozen cases × {upstream_map, control, exp, mlx} -> results/ane-r3-model/
```

`ANE_FORCE_PLAIN_FFN=1` makes the Qwen3 loader skip the residual-add FFN so the plain fused FFN (the kernel measured in R2) actually runs;
`ANE_TRACE_PATH=<file>` appends per-step top-16 logits. The kernel map line `R3 FFN kernel map: ...` on stderr says which FFN kernels ran. The frozen fixture is `r3/extraction_eval.json` (v2; v1 kept as `extraction_eval_v1.json`); the scorer is `r3/score.py`.

## R4 concurrent placement

```bash
.venv/bin/python -m prototype.r4.run_r4 --fg-model mlx-community/Qwen2.5-3B-Instruct-4bit   # 5 conditions, 3 × 300 s windows -> results/ane-r4-concurrent/
.venv/bin/python -m prototype.r4.what_changed                                                  # docs/R4-what-changed.md from the recorded results
```

Foreground on the GPU (MLX), background extraction on the GPU (token-boundary preemption) or on the ANE (ane.cpp serve, one session).
One background placement is resident at a time (memory guardrail). Energy needs a `sudo powermetrics --samplers cpu_power,gpu_power,ane_power -i 1000`
text log passed as `--power-log`; without it energy is reported unavailable.
